# Liquid glass and visible training graphs

The app keeps Dashboard / Workout / + / Levels / More, its compact one-exercise logger, explicit target acceptance and existing save/sync behavior. Shared light/dark theme tokens now live in the final design stylesheet; the three preceding layout layers no longer redefine those themes. Frosted cards, floating navigation, timer controls and sheets share surface, border, shadow and control rules. Inner plots and numeric inputs have stable readable surfaces. Reduced motion, increased contrast, reduced transparency where supported, forced colors and browsers without backdrop filtering have fallback rules. No visual preference is added to persisted state.

The Dashboard shows weekly training-day progress, completed primary work, 4/8/12-week training-day and actual bodyweight plots, recent records, XP and recent workouts without a hidden-panel carousel. Levels uses a common numeric scale for muscle bars and shows the selected muscle's weekly work. Previews, weekly review and recaps have labelled primary-set comparisons; indirect and advanced work stay separate. Lift progress retains the existing comparable-repetition graph and adds separate observed-load/reported-RIR plots in the selected context. Filters remain accessible in a compact disclosure. PR comparisons use the existing observed record calculations and units. The share poster uses a composited light glass palette; it does not include additional personal fields.

Graphs use saved observations, never generated performance or physiological estimates. Unique training-day counts follow the existing reward eligibility; zero-work weeks are not missed-volume obligations. Bodyweight uses the latest actual daily report and stops lines across gaps exceeding a week. Future reports are excluded. Lift plots break across missing/excluded observations; unknown effort is never filled in. The body map's primary count now reuses the existing advanced-bout classifier so legacy advanced entries cannot appear as ordinary straight sets. Coaching policy, progression caps and reward calculations are unchanged.

Graphs provide tap/keyboard inspection, labelled dates/units and exact-value tables. Numeric bars use a shared zero-based scale; effort plots use 0–10 RIR. Trend windows default to eight weeks. Changing charts, scope, range or disclosures does not persist changes to training data. Programs, sessions, drafts, accounts, backups, APIs and database schemas remain compatible.

Release gates include chart-data regressions, the existing unit/type/build/security checks, isolated Worker/D1 and profile checks, 360/390px and desktop browser flows, offline resume, reduced motion/opaque contrast, target acceptance and the complete log/save/backup flow. Tests tied to the old ring geometry and carousel are updated to the replacement UI's behavior. Hosted verification uses real deployed assets with intercepted synthetic training data. Physical iPhone/Safari rendering must be reported separately from Chromium verification.

Exercise-order verification also caught a pre-existing persistence bug: cloning the whole state inside the Immer edit boundary failed on its draft proxy, while the UI could still report success. Order saving now changes only the selected routine order with immutable updates, waits for the existing durable-save interface, and reports the result inside the queue. The real Worker test verifies a genuinely changed routine order and unchanged completed history before testing swipe/Undo.
