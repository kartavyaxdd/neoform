## Measured dashboard geometry

The official 702px image includes phone hardware and system chrome. Its app viewport is approximately 626px wide. Ring diameters are approximately 138 / 250 / 138px, giving a centre-to-side ratio of 1.81. The implementation uses 1 / 1.82 / 1 grid proportions with aligned label baselines. The comparison must account for this crop and scale without hiding differing app controls or data.

The rings describe primary working sets, unique exercises and primary muscles. Targets are one cycle of the first non-archived program at its current phase, using `phaseTarget`; no new recommendation is generated. No active program means no invented target. Scope filters actual session program IDs. Observed PRs reuse the logger comparator, exclude initial baselines, and remain distinct from effort-confirmed reward eligibility.

Myorep, drop-set and giant-set sequence targets are excluded from ordinary ring targets, matching the existing completion counter's exclusion of activation/mini/drop/giant bouts. They remain separately available in Levels. They are not converted into ordinary set equivalents. Straight, down, paired and tempo rows retain their existing raw primary-set counting behavior.

The weight chart displays only real dated reports from coaching settings or saved sessions, keeping the latest observation per day within seven days. One measurement produces a point, not an invented line. No measurements produces an empty state. It is not a fitted or smoothed physiological trend.

The official help articles were also inspected: [dashboard widgets](https://help.macrofactorapp.com/en/articles/276-understanding-the-widgets-at-the-top-of-the-workouts-dashboard), [weight trend](https://help.macrofactorapp.com/en/articles/278-weight-trend-workouts), and [logging](https://help.macrofactorapp.com/en/articles/310-how-to-log-a-workout). They establish further gaps: MacroFactor's Recent Records offers Volume / Reps / Estimated 1-RM categories, and its Weight Trend is smoothed. NEOFORM currently shows observed comparable PRs and a chart explicitly labelled Recorded. These preserve the approved training semantics but do not establish exact parity with those widgets. The weight tile opens the existing bodyweight/coaching preferences so it has a real editing destination.

## Typography and asset provenance

DM Sans and Michroma are bundled locally, unmodified, from the Google Fonts repository with their SIL Open Font License files alongside the fonts. DM Sans follows MacroFactor's public marketing typography guidance; that is not evidence of the exact native app font. Michroma approximates the supplied extended geometric dashboard heading and is not asserted to be the original font. No proprietary font extraction, branded app images or screenshot-as-interface implementation is used.

Sources: https://macrofactor.com/brand-guidelines/ ; https://github.com/google/fonts/tree/main/ofl/dmsans ; https://github.com/google/fonts/tree/main/ofl/michroma

## Verification boundary

`reference-fidelity.spec.ts` checks real scope changes, ring proportions, observed records, actual weight points, exercise information tabs, unknown RIR, left close placement, both themes, offline font availability and overflow. It creates synthetic accounts/data only in isolated Worker/D1 QA. Other existing release suites retain the full logger / undo / reorder / finish / save / import / backup / coaching checks. These are functional and layout gates, not proof of 100% visual fidelity.

Generated screenshots and comparison artifacts belong under ignored `.qa-state`. Production verification must intercept all workout storage requests with isolated synthetic data and verify the full release SHA; never inspect the public workspace's actual personal records.
