# Gemini coach and richer glass

Gemini chat, recommendation explanations and program generation/review are available inside the authenticated, locked Sharma profile. Abhishek and anonymous public visitors cannot reach these APIs. Ordinary private accounts retain their existing Gemini capability. The API key is entered in More → Gemini coach & connection, encrypted server-side using the existing installation master, and never returned, exported or placed in browser storage. Do not hardcode provider credentials in source or paste them into chat.

The additive `0007_profile_ai_keys.sql` table separates profile credentials from private-account credentials and training persistence. AES-GCM binds Sharma's ciphertext to `workspace-profile:sharma`. Every profile AI request requires the authenticated cookie, the server-selected locked profile and the matching account header. Mutations retain same-origin checks. Key rotation cancels existing generation leases; responses are fenced against a changed key. Test connection checks key/model access without generating a reply.

Coach requests contain a bounded, read-only snapshot of the current program, recent saved workouts, explicitly reported effort/recovery and deterministic review reasons. Profile names and private notes are omitted. Setup, technique, order, phase and assigned-versus-actual values remain distinct. Unknown observations stay unknown; coverage describes truncation. A selected recommendation includes its proposed targets, evidence and exclusions. Only a short recent conversation is sent. Closing the sheet or switching profile clears its conversation and cancels pending work.

The existing pinned Gemini model, stateless Interactions transport, no-tool policy, global daily generation allowance and validation remain. Chat shares that daily allowance, with a bounded ten-request chat burst; program generation retains its three-request burst. There are no retries, model substitutions or template fallbacks. Replies must satisfy a strict schema, usage proof and supplied-reference allowlist. Prompt guidance is not a guarantee of accuracy: chat is a second opinion, cannot execute changes, and does not replace the deterministic target engine. Generated programs still pass the existing conservative schema/domain checks and editable preview before explicit saving/activation. The book is never uploaded.

Glass surfaces use stronger edge highlights, depth and blue/violet/teal ambient lighting in both themes. Logger inputs and graph interiors remain solid and readable. Existing reduced-motion, reduced-transparency, high-contrast and unsupported-blur fallbacks remain in force.

Verification uses synthetic profiles, credentials and training only. Real isolated Worker/D1 gates cover profile authorization, encrypted key CRUD and unchanged training state; upstream replies are mocked for deterministic provider and browser checks. A genuine user key must be entered and tested in the app before claiming live model generation. Physical iPhone/Safari rendering requires a device check.
